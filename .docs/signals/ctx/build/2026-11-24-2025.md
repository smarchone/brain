## Decisions
- Scratch all previous ctx; rebuild ctx from this session only.
  why: the user's call; the pipeline replaces the old recall design
  not: reconciling the old context/, sessions/, golden/ ctx
- The brain is a conversation pipeline: its output is the next good conversation; insights are what that conversation produces.
  why: agent experience over bookmarks
  not: a bookmark store; a retrieval layer for agents
- Pipeline: dump → ingest → backlog → session: triage → infer from insights → convo → insights, compounding.
  why: the user's design
  not: yard → infer → convo with processing inside infer
- Dump only dumps; all processing is ingest.
  why: by dump the user meant just dumping
  not: processing at dump
- Ingest processes one item into talkable form, doing whatever fits the media.
  why: the user's words: "processing, summarization etc... whatever fits the usecase"
  not: one fixed summarizer
- Triage can pick multiple related backlog items.
  why: the user's call
  not: one item per session
- Infer runs at session start from the current insights to drive a better conversation.
  why: the user's design; better conversations lead to better insights
  not: inferring at ingest
- Build on plain files, not on an existing memory layer.
  why: Mem0 drops the argument; Meko is multi-agent infrastructure; neither ingests media or prepares conversations
  not: Mem0, Meko or a vector store
- Ingest runs in the background right after a dump; leftovers are ingested at session start.
  why: the dump returns at once and sessions start from ready items
  not: ingest only at session start; blocking the dump
- Triage ranks clusters by tension, usually 2-4 items.
  why: tension makes a conversation worth having
  not: FIFO; newest first
- Infer opens on a question or tension, never a summary.
  why: a summary is a reading digest
  not: "here's what these items say"
- Insights merge: add, update or replace.
  why: insights must say what is true now
  not: append only
- Settled items leave the backlog; unreached items stay unchanged.
  why: a session clears what it used and nothing else
  not: a verdict on every picked item
- Verdicts are distilled or released; parked is dropped.
  why: an unreached item already waits in the backlog
  not: parked with a when: trigger
- The user starts every session; nothing runs on a schedule.
  why: interruptions bring back context-switching cost
  not: reminders or scheduled sessions
- One command, two verbs; no backlog shown; a session opens with one prepared cluster.
  why: the agent prepares, the user drives
  not: a menu of saves
- "Backlog" is internal vocabulary only.
  why: naming the stage must not turn into showing the pile
  not: a user-facing inbox
- A dump and its ingest output live in one file in yard/; insights.md is one file; settled dumps move to archive/; brain stays private; global skill symlinked from skill/.
  why: one record per item, small insights for every infer, private material
  not: separate stores; one note per thread; per-project brains
- Statuses: dumped → ingested → distilled | released.
  why: the status is the stage
  not: yard/parked statuses
- brain.py only finds, lists and fetches transcripts.
  why: judgment stays with the model
  not: scripted clustering
- Transcripts from captions via yt-dlp, no audio download.
  why: no local speech-to-text
  not: audio transcription
- `brain.py yard` prints each ingested dump's claim.
  why: triage compares claims without opening files
  not: the raw first line
