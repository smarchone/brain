## Decisions
- Convo to insights uses progressive summarization.
  why: the user's call
  not: keeping only the conclusion
- Raw convo plus summary are stored in convo/<date>-<name>.md; convo is bucketed by session.
  why: the user's design
  not: log.md entries
- Insights are bucketed by topic.
  why: the user's design
  not: one insights.md
- insights/index.md lists topics; triage and the session read it.
  why: the user's call
  not: reading every topic file
- convo files hold Summary and 2-4 Key turns above the raw Conversation; the summary is the session log.
  why: layers 4 and 2-3 of progressive summarization; one file per session replaces log.md
  not: a separate log.md
- The raw conversation comes from the session log via golden's extractor.
  why: an agent recalling a conversation paraphrases it
  not: the agent writing it from memory
- Index lines: topic file, the user's current stance, last update.
  why: triage can match a cluster to topics from one line
  not: listing every insight in the index
- Add a topic only when none fits; merge topics that draw the same dumps.
  why: few topics keep the index readable
  not: one topic per session
- Replace keeps no stale insight; convo files keep the history.
  why: insights say what is true now
  not: versioned insights
- The first session's transcript is restored from git history (305d770) into convo/, tool lines stripped.
  why: its raw conversation existed and nothing is lost
  not: a summary-only convo file
- The brain insight is updated to the conversation-pipeline wording from this session.
  why: the old wording ("yard → daily log → insights") no longer matches what the user decided
  not: keeping the stale wording
- brain.py convo imports golden.py's loader at run time; a convo starts at the last bare /brain and runs to the end.
  why: one extractor for both skills; /brain <thing> is a dump
  not: a vendored loader; the whole session
