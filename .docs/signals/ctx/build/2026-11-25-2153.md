# Session 2026-11-25-2153: golden sync rework — public citations, learning/aha insights, convo catalog
> Ctx-only build: records the decisions behind the sync-golden rework already in skill/ and brain/.

## Steer
- Insights from golden sessions cite the public golden page (`https://smarchone.github.io/golden-convo/#<id>`) directly; no convo/ file is made for a golden session.
  why: golden sessions are public and hosted already; a stub per session duplicated title and why and filled convo/ with files that aren't brain conversations
  not: a convo/ stub per golden session holding its Summary and labels (the earlier design)
  by: human
- An insight is memory with a purpose: it makes later conversations better and lets them compound. It holds only two kinds, prefixed on each entry: `learning:` (what the user concluded or came to understand) and `aha:` (a connection that clicked). Facts are not stored in insights; they stay in the convo and are read through the backlink when a conversation needs them.
  why: the user wants beliefs, learnings and aha moments remembered without the noise of stored facts; a fact a learning rests on is one hop away
  not: conclusions only (dropped what the user learned from a session); also storing facts, taste and interests (too much becomes noise; "for now")
  by: human
- Each insight carries its own context: the claim names what it's about (the product, idea, system or situation), never a bare "it", "the report" or "this".
  why: an insight is quoted alone into a later conversation; without its subject it can't be understood or pushed on
  not: relying on the topic file or the source for context
  by: human
- An insight's second line carries two backlinks: the web link for the viewer, then the file path (`$GOLDEN_REPO/<YYYY-MM>/<id>.md` or `convo/<file>.md`) for progressive disclosure.
  why: the web link renders in the app; the path lets an agent open the source with a plain file read
  not: the web link alone (the agent needs a script or a fetch to drill down)
  by: human
- `brain/catalog.md` is a cached registry of every convo, brain's and golden: title, why, labels and path, newest first, like a skill's name and description. A /brain session's entrypoint is the catalog plus `insights/index.md`; topic files and convos open only on demand.
  why: the pattern of how coding agents register skills: descriptions always loaded, bodies loaded when needed
  not: insights/index.md alone as the entrypoint (past convos were invisible to triage); reading convos at session start
  by: human

## Build 1
built: ctx-only; the code already shipped this session (skill/SKILL.md, scripts/brain.py, app/view.html, README.md, brain/) · verified: `brain.py catalog` writes 43 entries with escapes decoded; `brain.py golden` lists 0 unsynced; `golden --read` prints the two-link cite line; serve.py builds the page. Not verified: a full /brain session on the new entrypoint.
- `brain/golden.md` is the golden sync ledger, one line per synced session: `- <id> · <topics, or "nothing kept"> · synced <YYYY-MM-DD>`; `brain.py golden` treats a session as synced when it's listed there or a brain convo carries its session_id.
  why: with no convo/ stub, sync state needs a home, including sessions that kept nothing so they aren't listed again
  not: deriving sync state from insight citations alone (a session with nothing kept would be offered forever); state outside the brain folder
  by: agent
- At golden sync, saving a session as golden counts as the user endorsing its `why`, so a `why_source: suggested` why can stand as a learning when nothing else in the session states it.
  why: sessions where the user mostly asked kept nothing, though the user chose to save them
  not: treating a suggested why as never the user's
  by: agent
- No compression rule for large topics for now: topics grow without a size-triggered merge.
  why: the user reverted it; not wanted yet
  not: proposing merges once a topic passes about 15 entries
  by: human
- `brain.py catalog` builds catalog.md from the frontmatter of convo/ and $GOLDEN_REPO, decoding `\uXXXX` escapes left by quoted YAML; it's generated, never edited, and rebuilt at session start, after Close and after sync.
  why: a deterministic rebuild can't drift from the files, unlike golden-convo's own posts.json (39 of 41)
  not: a hand-maintained catalog; reading golden-convo's posts.json
  by: agent
- `brain.py golden --read <id>` prints the golden file's path and the cite line; it writes nothing. `GOLDEN_URL` overrides the public base URL.
  why: sync no longer creates files; the cite line keeps both backlinks consistent
  not: `--pull` writing a convo/ stub
  by: agent
